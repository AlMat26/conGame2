# Прогресс разработки

Документ для агентов и автора: что сделано, что дальше, какие решения приняты.
**Обновляй его** после завершения этапа или заметной части работы:
статус этапа, отмеченные задачи, новые решения и известные проблемы.

## Игра

Консольный многопользовательский выживач, вид сверху.
Процедурный остров с водой, берегом, лесами и скалами; копание и стройка;
шахты с подземными слоями, укрепление тоннелей и обвалы.

## Принятые решения

| Вопрос              | Решение                                                        |
|---------------------|----------------------------------------------------------------|
| Платформа           | только Linux (включая Termux)                                  |
| Время               | реальное время, кадр 30 мс; движение не чаще раза в 30 мс      |
| Мир                 | ограниченный (256×256, остров в океане), но из чанков 32×32 — задел на бесконечный |
| Игроки              | 2–4 друга; хостом выступает один из игроков                    |
| Графика             | вариант A: классический ASCII, символ на чёрном фоне, 8 цветов, без юникода |
| Генерация           | детерминированная по seed: по сети передаётся seed и изменения, а не карта |
| Сеть                | сервер решает всё: клиент шлёт намерения, сервер рассылает результат |
| Сокеты              | неблокирующие, опрос каждый кадр в том же потоке (без потоков и async) |
| Протокол            | текстовые сообщения `ТИП аргументы…` поверх рамки «длина + данные» |
| Выход хоста         | игра заканчивается у всех (миграции хоста нет)                 |
| Действия            | по направлению взгляда (последний шаг, даже упёршийся); клетка перед игроком подсвечена |
| Под постройками     | исходная земля берётся из генератора (`getGroundTile`), отдельно не хранится |
| Мосты               | можно строить и на мелкой, и на глубокой воде                  |
| Внешний вид тайлов  | вид по выбору агента (автор не задавал): `T`/`^` деревья, bold-песок, пена у берега — автор может поправить |
| Симуляция мира      | только у хоста (и в одиночной игре); клиенты получают результат |
| Подземелье          | 8 уровней шахт (`mineDepth`); на поверхности 4 входа `>` у подножия скал; на уровнях лестницы `<` / `>`, штольни заброшенной шахты, пещеры, руда. Переход — шагнуть на лестницу |
| Темнота             | только под землёй (на поверхности день). Свет от источников (`LightSource`), сквозь непрозрачное не проходит. Уровни символами: ярко — тайл, 2 — тайл синим, 1 — `:`/`.` синим, 0 — ничего |
| Крепь и обвалы      | копать под землёй можно и без дерева. Если дерево есть — крепь `+` ставится по бокам прохода сама (1 дерево). Выкопанная игроком клетка держится, если в радиусе 2 есть крепь или стена или если в квадрате 3×3 вокруг меньше 7 выкопанных клеток (тоннели шириной 1–2 стоят сами, зал от 3×3 — нет). Иначе через 2 с обвал: клетки засыпает завалом `%`, клетку с игроком — нет. Природные пещеры и старые штольни не обваливаются |
| Инвентарь           | пока только счётчики у игрока: дерево (дерево +2, крепь +1) и руда (заглушка `*`, +1). Хранит хост, клиенту — `INV` |
| Стены и мосты       | пока бесплатные (решение этапа 3); тратить ли на них дерево — открытый вопрос к автору |
| Библиотеки          | ncurses, Boost.Asio (только заголовки); шум генерации — свой    |

## Этапы

| #  | Этап                                                      | Статус      |
|----|-----------------------------------------------------------|-------------|
| 0  | Рефакторинг старого кода: сеть, рендер, сборка            | ✅ готово   |
| 1  | Мир и ходьба одного игрока                                | ✅ готово   |
| 2  | Сеть: seed и позиции игроков, игра вдвоём и больше        | ✅ готово   |
| 3  | Копание и установка блоков с синхронизацией               | ✅ готово   |
| 4  | Живой мир: прочность, рост деревьев, прибой, внешний вид   | ✅ готово   |
| 5  | Шахты: подземные уровни, темнота, крепь, руда, дерево     | ✅ готово   |
| 6  | Факелы: ставятся игроком, освещают шахты                  | ⏳ следующий |
| 7+ | Виды руды, крафт, голод, день и ночь…                     | —           |

### 0. Рефакторинг — готово

- [x] `Network` разделён на `NetworkServer` и `NetworkClient`, исправлено падение
      в деструкторе и утечки
- [x] `send` / `receive`: 4 байта длины (big-endian) + данные, лимит 1 МБ
- [x] ошибки сети возвращаются как `false`, без исключений
- [x] `ConRender`: неблокирующий ввод, `erase()` без мерцания, отсечение за краем
      экрана, цвета, `KEY_RESIZE`
- [x] аргументы командной строки `host` / `join`
- [x] актуальный Boost.Asio API, CMake 3.10, `build/` убран из репозитория

### 1. Мир и ходьба — готово

- [x] модуль `World/`: тайлы, ленивые чанки 32×32, мир 8×8 чанков
- [x] генерация: фрактальный value noise по seed → глубокая вода / мелководье /
      песок / трава / скала; второй шум — лес; спад высоты к краям → остров
- [x] точка появления — трава без препятствий в радиусе 2
- [x] модуль `Game/`: игровой цикл, ходьба (стрелки / WASD), камера на игроке, HUD
- [x] анимация воды: бегущие диагональные «волны» `~` → `-`
- [x] `congame play [seed]` для воспроизводимого мира

### 2. Сеть — готово

- [x] неблокирующие сокеты: приём игроков и сообщения обрабатываются каждый кадр,
      игровой цикл не останавливается
- [x] протокол: клиент → хост `MOVE dx dy`; хост → клиент `WELCOME id seed`,
      `POS id x y`, `LEAVE id`, `FULL`
- [x] хост — игрок 0, принимает до 3 клиентов, 5-й получает `FULL`
- [x] клиент получает seed и id, строит тот же мир; новичок получает позиции всех
- [x] хост проверяет ходы: соседняя клетка, проходимость, игроки не проходят
      друг сквозь друга, не чаще раза в 30 мс (спам `MOVE` не ускоряет)
- [x] у каждого игрока свой цвет `@`; HUD: адрес хоста, число игроков, свой цвет
- [x] отключение клиента (в т.ч. `kill -9`) — игрок исчезает у всех;
      выход хоста — у клиентов «Disconnected from host»; мусор от клиента
      и огромный заголовок — закрывается только это соединение
- [x] `host` / `join` запускают игру вместо теста соединения

### 3. Копание и стройка — готово

- [x] игрок смотрит в сторону последнего шага (даже если шаг упёрся в препятствие),
      клетка перед ним подсвечена (символ чёрным на цвете тайла)
- [x] `e` — копать / рубить: дерево → трава, скала → каменный пол (`.` белый),
      стена → исходная земля, мост → вода (если на мосту никто не стоит)
- [x] `r` — строить: на траве / песке / каменном полу → стена (`#` жёлтый),
      на воде (мелкой и глубокой) → мост (`=` жёлтый, проходим)
- [x] нельзя строить на клетке с игроком; действие не чаще раза в 150 мс
- [x] без инвентаря: блоки бесконечные, всё ломается с одного удара
- [x] сеть: клиент шлёт `DIG dx dy` / `BUILD dx dy`, хост проверяет и рассылает
      `TILE x y type`; хост хранит все изменения (`changedTiles`) и отдаёт их
      новичку сразу после `WELCOME`

### 4. Живой мир — готово

- [x] прочность: дерево — 3 удара, скала — 5, стена — 4, мост — 2, росток — 1;
      повреждённая клетка красная; без ударов 3 с повреждение сбрасывается
- [x] деревья отрастают: на месте срубленного через 60 с росток `"`, ещё через 90 с
      дерево (если на клетке стоит игрок — откладывается); срубленный росток не отрастает
- [x] прибой: мелкая вода у берега вспыхивает белой пеной, на мелководье блики `-`,
      по глубокой воде бегут диагональные волны
- [x] песок ярко-жёлтый (bold), стены и мосты остаются тёмно-жёлтыми («дерево»)
- [x] деревья ярко-зелёные, два вида: `T` (лиственные) и `^` (хвойные, ~25%);
      на траве изредка `'` — чтобы не было «обоев»
- [x] сеть: хост рассылает `DAMAGE x y hits` (0 — сброс); рост и сброс считает
      только хост (`updateWorld`), клиенты получают `TILE`

### 5. Шахты — готово

- [x] мир по слоям: `z = 0` — поверхность, `z = -1 … -8` — уровни шахт
      (`World::getTile(x, y, z)`), чанки по слоям, всё лениво
- [x] шахты расставляются при создании мира (`generateMines`, `std::mt19937`
      от seed): 4 входа на траве у скал, по 3 лестницы вниз на уровень; комнаты
      у лестниц и штольни «Г» от лестницы вверх к ближайшей вниз и обратно;
      стены штолен — крепь `+` через клетку; пещеры и рудные жилы — шум
- [x] переход между уровнями — шагнуть на `>` / `<`; появляешься на парной
      лестнице; если там стоит игрок — не пускает
- [x] темнота под землёй: свет от игроков (сила 8), прямая видимость (Брезенхэм),
      стены получают свет от освещённого пола рядом; уровни света — символами
- [x] другие игроки видны только на своём уровне и только в освещённых клетках
- [x] копать под землёй можно без дерева; если дерево есть — −1 дерево и крепь
      по бокам автоматически
- [x] обвалы: после копания проверяется устойчивость выкопанного рядом
      (`isStable`: крепь / стена в радиусе 2 или < 7 выкопанных клеток в 3×3);
      неустойчиво — подсказка «The ceiling is cracking!», через 2 с завал `%`
      (2 удара), всем рядом — «Cave-in!»; игрока не засыпает, но может запереть
- [x] инвентарь: дерево (дерево +2, крепь +1), руда-заглушка (+1);
      прочность: руда — 6, крепь — 2, завал — 2
- [x] HUD: глубина, дерево и руда, подсказки над нижней строкой
- [x] сеть: `z` в `POS` / `TILE` / `DAMAGE`; новые `INV wood ore` и `NOTE текст`

### 6. Факелы — следующий

Система освещения уже рассчитана на них: каждый кадр `Game::collectLights`
собирает источники (`LightSource`: x, y, сила) на уровне игрока, `computeLight`
считает освещённость от всех сразу. Факел — ещё один источник.

- [ ] тайл факела (например `i` или `!`, жёлтый bold), ставится на пол по `r`
      под землёй (или отдельной клавишей) и стоит дерево (+ руду?)
- [ ] `collectLights`: добавлять факелы на видимом участке уровня — искать
      тайлы факела в прямоугольнике экрана, расширенном на силу факела
- [ ] сила факела больше, чем у игрока (например 10)
- [ ] (по желанию) мерцание: сила факела ±1 по времени
- [ ] факел можно забрать обратно (`e`) — возвращает материал
- [ ] сеть: факел — обычный тайл, уходит через `TILE`, отдельного протокола не нужно

## Известные проблемы и долги

- Ctrl+C завершает игру без `endwin()` — терминал остаётся без эха (`reset`).
  Выходить нужно через `q`.
- Подключение к недоступному IP блокирует запуск клиента до системного таймаута
  (до ~2 минут); выйти можно только Ctrl+C.
- Только IP-адреса, имена хостов не разрешаются.
- Хост показывает первый не-loopback IPv4; при VPN / Docker это может быть
  не тот адрес, который нужен друзьям.
- Предсказания на клиенте нет: свой ход виден после ответа хоста (в локалке
  незаметно, через интернет будет задержка).
- Юникода нет: `ConRender` отсекает строки по байтам. Если понадобится —
  ncursesw и подсчёт символов.
- Блоки бесконечные (инвентарь — этап 7+).
- Изменения мира новичку отправляются по одному сообщению `TILE` на клетку;
  при тысячах изменений вход станет медленнее — тогда упаковать в одно сообщение.
- Изменения мира живут только в памяти хоста: сохранения мира нет.
- Свет других игроков виден, даже если их самих не видно из-за стен: освещённость
  считается от всех источников, без проверки видимости от смотрящего.
- Стоящий на нижнем конце лестницы игрок не даёт другим спуститься.
- Какие клетки выкопаны игроками (`dugCells`), знает только хост, в памяти;
  сохранения нет.
- Игрок, стоящий в центре зала 3×3, спасает его от обвала (свою клетку
  не засыпает, а остальные клетки зала 3×3 сами по себе устойчивы).
- Внешний вид (символы деревьев, bold-песок, частота пены) выбран агентом
  и автором вживую ещё не оценён.
- Таймеры роста деревьев живут только у хоста и пропадают при его выходе.
- Сборка под Termux не проверялась.

## Как проверять

Сборка без предупреждений с `-Wall -Wextra`. Игру удобно гонять в псевдотерминале
через Python `pty` + `pyte` (эмулятор терминала) с `TERM=screen`: в `TERM=xterm`
ncurses сжимает повторы последовательностью REP, которую `pyte` не понимает.
Для проверки памяти — сборка с `-fsanitize=address,undefined`.

Для шахт — вспомогательная программа на C++ (`route`), которая по тому же seed
строит маршрут BFS по `World` до нужного тайла (вход, крепь, руда, лестница)
и выдаёт клавиши; маршрут считается по исходному миру и не знает о раскопках.

Для долгих таймеров (рост деревьев) — собрать копию проекта во временной папке,
заменив в ней константы `saplingTimeMs` / `treeGrowTimeMs` на 2000; в репозитории
константы не трогать.

Сеть проверяется так же: хост и клиенты в отдельных псевдотерминалах, у каждого
свой `pyte.Screen`. Чтобы дойти до дерева / скалы / воды, тест ищет путь BFS
по экрану (мировые координаты = позиция из HUD + смещение от центра экрана); поведение хоста при плохих клиентах — сырым TCP-сокетом
из Python (рамка `struct.pack(">I", len)` + текст).
