# Прогресс разработки

Документ для агентов и автора: что сделано, что дальше, какие решения приняты.
**Обновляй его** после завершения этапа или заметной части работы:
статус этапа, отмеченные задачи, новые решения и известные проблемы.

## Игра

Консольный многопользовательский выживач, вид сверху.
Процедурный остров с водой, берегом, лесами и скалами; копание и стройка;
шахты с подземными слоями, укрепление тоннелей и обвалы.

## Принятые решения

| Вопрос              | Решение                                                        |
|---------------------|----------------------------------------------------------------|
| Платформа           | только Linux (включая Termux)                                  |
| Время               | реальное время, кадр 50 мс; сервер будет работать тиками       |
| Мир                 | ограниченный (256×256, остров в океане), но из чанков 32×32 — задел на бесконечный |
| Игроки              | 2–4 друга; хостом выступает один из игроков                    |
| Графика             | вариант A: классический ASCII, символ на чёрном фоне, 8 цветов, без юникода |
| Генерация           | детерминированная по seed: по сети передаётся seed и изменения, а не карта |
| Сеть                | сервер решает всё: клиент шлёт намерения, сервер рассылает результат |
| Библиотеки          | ncurses, Boost.Asio (только заголовки); шум генерации — свой    |

### 0. Рефакторинг — готово

- [x] `Network` разделён на `NetworkServer` и `NetworkClient`, исправлено падение
      в деструкторе и утечки
- [x] `send` / `receive`: 4 байта длины (big-endian) + данные, лимит 1 МБ
- [x] ошибки сети возвращаются как `false`, без исключений
- [x] `ConRender`: неблокирующий ввод, `erase()` без мерцания, отсечение за краем
      экрана, цвета, `KEY_RESIZE`
- [x] аргументы командной строки `host` / `join`
- [x] актуальный Boost.Asio API, CMake 3.10, `build/` убран из репозитория

### 1. Мир и ходьба — готово

- [x] модуль `World/`: тайлы, ленивые чанки 32×32, мир 8×8 чанков
- [x] генерация: фрактальный value noise по seed → глубокая вода / мелководье /
      песок / трава / скала; второй шум — лес; спад высоты к краям → остров
- [x] точка появления — трава без препятствий в радиусе 2
- [x] модуль `Game/`: игровой цикл, ходьба (стрелки / WASD), камера на игроке, HUD
- [x] анимация воды: бегущие диагональные «волны» `~` → `-`
- [x] `congame play [seed]` для воспроизводимого мира

### 2. Сеть — следующий

- [ ] протокол сообщений: тип + данные поверх существующего `send` / `receive`
- [ ] хост: генерирует seed, принимает до 3 клиентов, не блокируя игровой цикл
      (асинхронный accept или отдельный поток)
- [ ] при подключении клиент получает seed и id игрока, строит тот же мир
- [ ] клиент шлёт намерения движения, хост проверяет проходимость и рассылает позиции
- [ ] отрисовка других игроков
- [ ] отключение игрока, потеря связи с хостом — без падения
- [ ] `host` / `join` запускают игру вместо теста соединения

## Известные проблемы и долги

- Ожидание клиента на хосте блокирующее — отменить можно только Ctrl+C, после чего
  терминал остаётся без эха (`reset`). Решить в этапе 2.
- Только IP-адреса, имена хостов не разрешаются.
- Хост не показывает свой IP.
- Юникода нет: `ConRender` отсекает строки по байтам. Если понадобится —
  ncursesw и подсчёт символов.
- Деревья и скалы пока только препятствия (рубка и копание — этапы 3–4).
- Жёлтый (песок) в базовых 8 цветах во многих терминалах тёмный, почти
  коричневый; возможно, нужен bold. Символ дерева `T` — под вопросом.
- Сборка под Termux не проверялась.

## Как проверять

Сборка без предупреждений с `-Wall -Wextra`. Игру удобно гонять в псевдотерминале
через Python `pty` + `pyte` (эмулятор терминала) с `TERM=screen`: в `TERM=xterm`
ncurses сжимает повторы последовательностью REP, которую `pyte` не понимает.
Для проверки памяти — сборка с `-fsanitize=address,undefined`.
